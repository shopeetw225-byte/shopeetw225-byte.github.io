# 《放置事务所》首轮宣传方案

状态：访谈形成的可审阅草案；目标、定位、渠道与形式已经确认，以下排期、产量与执行细节待整体确认。未向外发布。

## 1. 已确定的方向

- 目标：让玩家加入 Steam 愿望单。
- 主句：**战斗自动进行，阵容由你研究。**
- 受众：构筑策略为主，轻松放置为辅，兼顾图鉴收集玩家。
- 覆盖：Steam、B站、小红书、YouTube、Reddit、X。
- 语言：简体中文、繁体中文、英语。
- 形式：实机画面与字幕；AI 配音为可选补充，静音观看也应完整理解内容。
- 素材：优先检查并使用现有素材，再补录或补做必要缺口。
- 推广：自然流量。没有硬性截止日期。

## 2. 商店页面如何讲

叙事顺序：构筑选择 → 自动战斗的实际结果 → 放置成长 → 收集与下一步目标。

先完成三语短描述和“关于这款游戏”图文初稿；英文独立润色，繁中检查术语与语气。品牌严格使用《放置事务所》／Idle Agency，避免自动转写改动正式名称。

准备至少五张当前版本实机截图，候选题材为编队、战斗、装备搭配、图鉴、放置收益。每张图对应一个明确卖点，优先选实际可读且已完成的界面；旧截图仅在版本及视觉核查通过后复用。

预告片建议45–60秒：开头直接展示队伍与战斗；中段解释一次有证据的构筑选择；后段简述放置与收集；结尾游戏名称和加入愿望单引导。先审旧脚本再决定复用段落。

胶囊封面先检查既有中英文版本的品牌、字形、小尺寸识别度和现行规格，列出最小修改清单。截图栏使用游戏实机图，卖点标题图放在详情区。遵循 [Steam 商店素材规范](https://partner.steamgames.com/doc/store/assets/standard)。

## 3. 首批三个主题

| 主题 | 玩家要看懂什么 | 需要的实机证据 |
| --- | --- | --- |
| 换个站位，谁能吃到光环？ | 阵容不是只看总战力，站位会影响队伍 | 相同角色、装备和对手下，站位改变前后的覆盖与结果；没有稳定胜负对照就只展示已验证效果 |
| 图鉴里这一位，怎么加入队伍？ | 收集有目标，新角色也有构筑用途 | 一名英雄的真实获取条件、取得过程及队伍用途 |
| 离开之后，回来能做什么？ | 放置资源如何支持下一次成长 | 真实收益、领取与升级过程；不虚构时长或收益倍率 |

三个主题各形成一份无字幕干净母版、字幕文本及封面候选；按渠道重剪，而非每个平台从零制作。首轮优先使用已经存在、足够清晰的录像；缺少证据时补录。

代码核查支持146名主集合英雄及四类图鉴，但具体画面、数值与获取过程仍需实跑确认。四类图鉴的“拥有／发现／击败”口径不同。旧稿的声望、具名连携等退场内容不进入新稿。

## 4. 渠道分工与语言

以下是第一轮测试安排，不是平台效果保证。

| 渠道 | 首轮内容建议 | 语言与引导 |
| --- | --- | --- |
| Steam | 三语商店文案、至少五张截图、一条预告片、现有胶囊检查 | 三语页面；愿望单为统一目标 |
| B站 | 一条60–120秒的构筑讲解，另从三个主题选两条短演示 | 简中；显著显示游戏名，引导到 Steam 搜索或可用链接 |
| 小红书 | 三个主题各一篇图文或短视频，封面提出具体玩法问题 | 简中；按实际可用入口设计引导，不假定所有外链都可点击 |
| YouTube | 一条完整玩法视频与三个短片主题 | 英语为发布主语言；完整视频提供简中、繁中、英语字幕，繁中短版先小规模测试 |
| X | 三个主题各一条原生短视频／图片帖，加一条游戏总介绍置顶候选 | 英语为主，繁中版本选择不同发布时段测试；带渠道区分的 Steam 链接 |
| Reddit | 找到允许相关展示的社区后，先做一至两篇具体玩法讨论 | 英语；明确开发者身份，以问题或机制为中心，按社区规则放链接 |

繁中覆盖包含完整 Steam 文案及视频字幕，不仅更换帖子的标题。不要求所有平台每条内容都发三个语言版本。

YouTube Shorts 描述与评论中的网址不可点击，需使用适用的频道链接或关联视频承接，发布前逐个测试路径。[YouTube 链接说明](https://support.google.com/youtube/answer/13748639)

X 可上传原生视频，素材时长与字幕方式在实际发布前按账户能力验证。[X 视频说明](https://help.x.com/en/using-x/x-videos)

Reddit 具体社区的自我推广限制需逐个检查，不批量复制同一广告帖。[Reddit 官方说明](https://support.reddithelp.com/hc/en-us/articles/360043504051-Spam)

## 5. 两周首轮安排（建议）

暂按每周六天、每天八小时，共12个工作日、96小时规划。若实际工时不同，保留阶段顺序并调整产量。

| 工作日 | 工作与验收结果 |
| --- | --- |
| 1–2 | 盘点素材、校正旧口径、确认商店地址与可访问状态；记录愿望单和访问基线；完成逐项素材可用／需修改／需补录清单 |
| 3–4 | 排出 Steam 三语文案、截图顺序和详情结构；检查现有胶囊，确定修改范围 |
| 5–7 | 制作预告片与三个核心主题；必要实机补录、字幕翻译与屏幕文字可读性检查 |
| 8–9 | 完成各平台标题、封面、文案、语言版本与链接；整包审阅 |
| 10–12 | 在用户明确授权发布后分批发布并检查实际路径；收集早期反馈，建立后续每周复盘表 |

最后三天仅能产生早期观察，不能据此断定哪个渠道长期有效。完整观察窗口建议覆盖首批发布后一周；不把制作阶段算作曝光测试。

## 6. 衡量与调整

- 主要结果：Steam 每日愿望单新增、移除与净变化；先记录基线，不凭空承诺数量目标。
- 渠道证据：可用时查看 Steam UTM 报告中的访问与愿望单转化，并保留具体内容编号。
- 内容诊断：曝光、观看／阅读、评论中对玩法的理解与商店访问。各平台指标定义不同，不直接混成一个转化率。
- 每条可追踪的外链使用一致命名，例如 `utm_source=x`、`utm_medium=organic_social`、`utm_campaign=wishlist_round1`、`utm_content=formation01_en`。最终链接须填入已确认的真实商店地址。
- Steam UTM 有自身统计与归因限制；将其与整体愿望单趋势并排看，不把未归因增长全部归功于某条内容。[Steam UTM 文档](https://partner.steamgames.com/doc/marketing/utm_analytics)
- 有观看但缺少商店访问：先检查引导与链接，再检查内容是否给出了进一步了解的理由。
- 有商店访问但愿望单反应弱：检查页面是否兑现视频中的玩法与视觉预期。
- 某主题持续带来有效兴趣：下一轮增加同类题材；低样本先继续观察，不做确定排名。

## 7. 开始执行前尚需确认的理解

- 是否采用上述首轮规模、两周制作与发布准备节奏，以及后续一周观察窗口。
- 是否接受语言分配：Steam 三语完整，国内平台简中，YouTube 英语主发布＋三语字幕，X 英语主发布＋繁中测试，Reddit 英语。
- 工时是否确为每周48小时。

商店公开状态、账号可用性、后台统计权限与最新可录制版本属于执行前事实核查；目前尚未核实。不因此提前承诺发布日或愿望单数量。方案确认后先制作与核查，向外发布由用户另行明确授权。
